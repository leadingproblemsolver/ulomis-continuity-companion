# Ulomis–ReferAll pilot claim-delivery matrix

## Outreach promise

> Your ReferAll work already names the problem: teams lose time across systems, spreadsheets and calendars. We’ll configure Ulomis on one live client thread and measure admin and re-entry saved. Use it once and correct only what matters.

This matrix defines what must happen before any part of that statement is treated as delivered.

| Promise element | Product mechanism | Recorded evidence | Failure boundary |
|---|---|---|---|
| “One live client thread” | `/pilot/david` qualification requires an active, client-facing, multi-source thread with an open loop and a natural return in 2–7 days. | Anonymous thread label, context, qualification checks, expected-return date, timestamp. | A synthetic, completed, unsafe, single-source, or actionless thread does not qualify. |
| “We’ll configure Ulomis” | David exports existing fragments; the operator imports them into `/pilot/workspace` and prepares all 12 operational-state fields. | Intake packet, source hashes, prepared-by value, prepared timestamp, source manifest, claim provenance and confidence. | The UI never claims autonomous ingestion or reconstruction. Founder assistance is visible throughout. |
| “Across systems, spreadsheets and calendars” | Intake accepts pasted excerpts, references and bounded files without requiring David to reorganize them. | Source kind, handling status, timestamp, content hash, included attachment manifest. | Links are references only; inaccessible links require a pasted excerpt. Excluded material is omitted from transfer. |
| “Correct only what matters” | Every material claim can be marked Correct, Partly right, Outdated, Unrelated or Missing. | Original claim, correction type, corrected value, reason, time, and any revised next action. | David is not asked to redesign the product, classify the whole workflow or polish non-material wording. |
| “Measure re-entry saved” | A self-reported baseline is locked before intake. On natural return, the operational state stays sealed until the live timer starts. | Baseline minutes and timestamp; confirmation/pause/start timestamps; observed interruption duration; early-return flag; timer start/end; observed seconds; reopened-source count; confidence change. | The baseline is not historical instrumentation and is labelled self-reported. An early return is marked as weaker evidence. Neutral and negative deltas remain visible. |
| “Measure admin saved” | Baseline admin time is recorded before intervention; actual admin time is recorded after re-entry. | Baseline/actual admin minutes and calculated delta. | Admin time cannot exceed the corresponding total re-entry window. Missing data is not converted into savings. |
| “Use it once” | One bounded setup, one confirmed state, one interruption, one measured return. | Stage transitions and local non-content audit log. | One thread can demonstrate an observed result, not repeatability or adoption. |
| “Deliver a continuation result” | The continuity view contains objective, current state, latest change, decision, rationale, commitments, dependencies, open items, missing information, owners, contradictions and one suggested next action. | Claim-level source references, type, confidence, last-confirmed date and participant confirmation timestamp. | No claim without evidence can leave the founder workspace. Suggestions do not execute decisions. |

## Required operational handoff

```text
David qualifies one thread
→ baseline locks
→ David adds existing fragments
→ intake packet is deliberately transferred
→ Salima verifies hashes and prepares the continuity state
→ David imports and corrects the draft
→ David confirms the thread
→ state is sealed during interruption
→ David starts the timer on genuine return
→ David records what he still reopened/contacted
→ measured result remains positive, neutral or negative
→ explicit second-thread, revise-once or stop decision
```

## Claim language allowed after one completed thread

Allowed:

> In this observed thread, David resumed X minutes faster/slower than his timestamped self-reported baseline, reopened Y fewer/more sources, and spent Z fewer/more admin minutes.

Not allowed:

- “Ulomis saves teams X%.”
- “Ulomis automatically understands client work.”
- “ReferAll adopted Ulomis.”
- “The result is repeatable.”
- “The pilot proved commercial value.”

A second real thread is the minimum behavioural test of repeated use. Payment or explicit internal sponsorship is a separate commercial test.
