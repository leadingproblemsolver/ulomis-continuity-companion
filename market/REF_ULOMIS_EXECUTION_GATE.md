## Single next externally consequential transition

**Gate 0 — deployment dry run, no customer data.**
On the actual served deployment and exact commit, complete the 13-step synthetic flow in `PILOT_OPERATOR_RUNBOOK.md`: intake → source/file hashes → deliberate transfer → 12 evidence-bound claims in workspace → prepared packet → participant material correction → confirmation → sealed interruption → timer/re-entry → outcome (including neutral/negative) → export/recovery → deletion. Verify mobile/desktop, Arabic switching and refresh boundaries. Record origin, commit, date, first failure or screenshots; do **not** claim browser verified before this.

**Gate 1 — one operator, one permitted live thread.**
Only after Gate 0 passes, ask the existing named operator for one active *redacted and permitted* client thread requiring at least two sources, unresolved work, and a naturally expected return in 2–7 days. Explicitly obtain participation and safe transfer permission. Decline material containing credentials, sensitive client information or outside permission. Do not imply automatic integrations, LLM extraction, encryption, authentication, or unattended action.

**Gate 2 — corrective first value.**
Lock the operator's self-reported baseline before intake. Produce source-linked state and actionable next action with field-level type, confidence and last-confirmed date. Participant **materially corrects or explicitly confirms** the state, accepts the next action, and seals the return. Reconstruct from permitted sources only.

**Gate 3 — natural return and settlement.**
Capture genuine interruption duration, actual time/sources/people reopened, admin effort, duplicate work and next action taken; retain neutral or negative findings. Ask for a *second live thread*, not abstract praise; only actual second use counts as repeated use. Price/sponsor only after verified continuation, and never claim revenue before payment/deposit or written internal sponsorship.
